# Проверка при разработке

Этот файл — полная версия раздела о разработке: что покрывает каждый набор, ручные проверки и заметки по отладке, помимо четырёх команд.

```sh
node --check lib/client.js
node --check lib/index.js
npm test                         # smoke-test (машина состояний) + host-route-test (хостовая половина) + page-bridge-test + host-fallback-test + relay-route-test + cordis-host-test + mac-notify-test + mac-notify-content-test + win-toast-test
npm pack --dry-run               # посмотреть, что попадёт в публикуемый tarball
```

## Что покрывает каждый набор и ручные проверки

**`smoke/smoke-test.cjs`** — офлайн-набор машины состояний. Он покрывает:

- три поколения хоста, общий переключатель и пять языковых режимов;
- мост быстрых решений, включая половину worker'а;
- определение простоя и самозакрытие уведомлений, отзыв оставшихся при возвращении, обработку длины тега;
- пробу, heartbeat и освобождение моста хоста страницы, а также форму `debug().hostBridge`;
- внешнюю пересылку: форму запроса Telegram, вердикт `ok` / `error_code`, повторы на 429 и 5xx, усечение до 4096, отбрасывание наполовину настроенных целей и полей токена и chat ID на странице настроек;
- тишину раундов Goal (молчит, пока проекция Goal `active`; одно уведомление о последнем раунде после остановки; старый хост без проекций всё равно напоминает);
- три случая нативных каналов Desktop: клик по телу нативного уведомления о подтверждении на Windows переключает только после POST на хостовый маршрут фокуса (а клик без сессии только поднимает окно); нативное уведомление без кнопок на Windows («нужен ответ» и «ответ готов» не идут через рендерер, клик по телу поднимает окно и останавливает опрос, «никогда не закрывать» ставит `persist`, а 5xx от хоста возвращает на страничный канал); а клик во фронтовом уведомлении macOS переключает через опрос раз в секунду и прекращает опрос после прочтения;
- что иконка уведомления идёт через хостовый маршрут `/__dsh-notify-me/icon.png` (уже не корневой favicon), и что сигнал засыпает по аудиочасам, а не по стенным — при позднем пробуждении (420 мс) последняя нота всё равно доигрывает, а второй сигнал на уже уснувшем контексте тоже паркуется после своей последней ноты;
- счётчик: два ожидающих дают 2, идентичный снимок ничего не перерисовывает, текущая сессия исключена, заглушение или выключение уводит обратно в ноль, а хост без `setAppBadge` молчит вместо исключения;
- `dockBadgeHostFailures()` — сторону отказа: бросающий снимок не мешает применить переключатель, ошибка попадает в `debug().dockBadgeError`, счёт перерисовывается, когда хранилище восстанавливается, а хост, отдающий только `setAppBadge`, очищается нулём.

Набор также фиксирует манифест: `dsh.client.inject` в `package.json` должен оставаться пустым, а рантайм-строка `inject = ["sessions", "locale", "slots"]` — как есть ([#44](https://github.com/chromoany/dsh-notify-me/issues/44): загрузчик читает этот список как «сначала приди этими целыми бандлами», поэтому недостижимая цель оставляет всю запись молча неактивной). `smoke/host-route-test.mjs` не требует локального DSH и прогоняет маршрут `lib/index.js`, его пробу и шлюз 403/405/501 на каждой платформе.

**Три новых набора** тоже поставляют собственный фейковый `ctx`, не требуют локального DSH и не трогают сеть:

- `smoke/page-bridge-test.mjs` прогоняет маршрут моста страницы: форму статуса, heartbeat и освобождение, отсутствующий заголовок намерения (403), cross-origin (403), плохой JSON (400), слишком большое тело (413), пропуск `Host`, производного от `allowedOrigins` (симулированный туннель), и коллизии путей.
- `smoke/host-fallback-test.mjs` прогоняет резервную отправку: дедупликацию подтверждений, троттлинг `turn/end`, пропуск субагентов, отсутствие отправки для среднего раунда Goal, пока Goal `active` (и отправку после `complete` / `pause` / `block`, и восстановление состояния Goal из журнала сессии после перезапуска), отсутствие отправки при свежем лизе, отправку после истечения лиза, немедленную отправку после `alive:false`, следование языка за heartbeat, перечитывание учётных данных после 401 и health-пробу.
- `smoke/relay-route-test.mjs` прогоняет ретранслятор: пробу `GET`, `405`, cross-origin `403`, `413`, `400`, `503`, отображение `200` / `502` и «ровно один повтор на 401», рендеринг `relay.bodyTemplate` и JSON-экранирование, отказ в регистрации маршрута при сломанном шаблоне на старте и лимит отрендеренного размера. В 1.24.0 добавились ещё две группы: тело завершения, дополненное из журнала сессии (переводы строк сохраняются, обрезается по лимиту и усекается, тело страницы со второй строкой не перезаписывается, `attention` не трогается), и `snippetLimit: 0`, пересылающий только название сессии, причём запрос, пришедший на публичный `Host`, проходит шлюз и всё равно не читает журнал.

**`smoke/mac-notify-test.mjs`** прогоняет маршрут уведомлений macOS: регистрацию только на хосте macOS Desktop, пробу, отказы 405 / 403 / 501 / 400, аргументы, переданные помощнику (включая `--id`, `--sound` и отзыв `{remove:id}`), и передачу клика, забираемую ровно один раз. Он подделывает платформу и версию Electron, не требует настоящего помощника и работает на любой платформе.

**`smoke/mac-notify-content-test.mjs`** прогоняет содержание уведомления:

- что `splitNotificationBody()` делает с каждой формой тела (одна строка, две строки, пустые строки, внешние пробелы, CJK, отсутствующие поля);
- что подзаголовок, поднятый самой страницей, побеждает разделение, а `--subtitle` передаётся только когда он действительно есть;
- что тело никогда не становится заголовком (регрессия);
- как берётся выдержка ответа из журнала событий: результаты инструментов пропускаются, всё сворачивается в одну строку, при длине обрезается с многоточием, пустой журнал не ошибка, а чтение идёт только для уведомления `done` с пустым телом;
- что неудачное чтение журнала всё равно отправляет уведомление;
- что каждая половина после разделения обрезается по своему лимиту (1000 символов для тела, 200 для подзаголовка).

Он тоже подделывает spawn, не требует настоящего помощника и работает на любой платформе.

**Язык и откат Android** получают свои случаи:

- `languageModes()` в `smoke/smoke-test.cjs` покрывает оба источника `auto` (локаль хоста и `document.documentElement.lang`); `zh-TW`, `zh-HK`, `zh-MO` и `zh-Hant` разрешаются в традиционный, `zh-CN` остаётся упрощённым; непоставляемый в пакете тег интерфейса (`ja`, `de`) читает английский; упрощённый берётся по умолчанию, только когда у страницы вообще нет языкового сигнала; закреплённый язык переключает и уведомления, и страницу настроек; а четыре словаря содержат ровно один и тот же набор ключей.
- `androidWorkerFallback()` покрывает три пути: на Android UA конструктор не трогается вовсе, регистрируется ровно один Service Worker, а опции уведомления (tag, renotify, silent, data) верны; на десктопном UA, чей конструктор бросает `Illegal constructor`, первое уведомление пробует его как обычно, откатывается на Worker и запоминает отказ; а Worker, который тоже отказал, оставляет ошибку в `debug().lastToastReject` вместо того, чтобы её проглотить.
- `smoke/page-bridge-test.mjs` дополнительно фиксирует, что heartbeat с `zh-TW` и `ru` принимаются, неизвестный язык игнорируется, а текст резервной отправки с хоста и приоритет `pickLanguage` соблюдаются.

**`smoke/win-toast-test.mjs`** прогоняет маршрут нативных уведомлений Windows:

- гейт Windows Desktop и пробу `GET`, отказы 405 / 403 / 501 / 400;
- полезную нагрузку подтверждения и её проход через base64;
- семь команд регистрации, записываемых перед первым уведомлением: три ключа протокола под `HKCU\Software\Classes\dsh-notify-me`, `DisplayName` и `IconUri` вместе с `CustomActivator` под `AppUserModelId\dsh-notify-me`, и пустая заглушка `CLSID\{…}` без `LocalServer32`; на Windows 10 их восемь (добавляется `LocalServer32` с указанием на `lib/win-toast-activator.ps1`);
- флаги `comActivation` и `persist` в полезной нагрузке (безкнопочное уведомление при «никогда не закрывать» уходит со `scenario="reminder"`) и аннотации маршалинга `LPWStr` в обратном вызове активатора;
- однократное получение действий approve / reject / open, истечение токена и отзыв `{remove}`.

Отсутствующий файл иконки не мешает регистрации: `IconUri` просто не пишется.

Он гоняет `reg.exe` и `powershell.exe` через фейковый `spawn`, поэтому не требует настоящего хоста Windows Desktop и работает на любой платформе. Он же утверждает, что сгенерированный скрипт-обработчик — UTF-16LE с BOM, чистый ASCII, содержит выражение `ExpandEnvironmentStrings` и не зашивает путь профиля, а тело уведомления открывает только `dsh-notify-me://open` (никогда `dsh://open`); `dsh-notify-me://open` без сессии по-прежнему разбирается как простой запрос поднятия ([#40](https://github.com/chromoany/dsh-notify-me/issues/40)).

Когда меняется `lib/focus-window.ps1` (только Windows), прогоните его и вручную:

```powershell
powershell -NoProfile -File lib/focus-window.ps1 -ProcessId 0   # последняя строка должна быть FOCUSED=1
```

`cordis-host-test.mjs` одалживает `@deepseek-ai/cordis` из локальной установки DSH (он по очереди проверяет глобальный каталог npm, `~/.dsh/profiles/web/node_modules` и плоский запасной вариант `~/.dsh/profiles/node_modules`). В checkout'е исходников без зависимостей профиля укажите путь через `DSH_CORDIS_PATH=<checkout>/vendor/cordis/lib/index.js`.
