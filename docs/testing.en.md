# Development checks

This file is the long form of the README's development section: what each suite covers, the manual checks and the debugging notes, beyond the four commands.

```sh
node --check lib/client.js
node --check lib/index.js
npm test                         # smoke-test (state machine) + host-route-test (host half) + page-bridge-test + host-fallback-test + relay-route-test + cordis-host-test + mac-notify-test + mac-notify-content-test + win-toast-test
npm pack --dry-run               # preview the published tarball
```

## What each suite covers, and the manual checks

`smoke/smoke-test.cjs` is the offline state-machine suite: three host generations + master switch + five locale modes + the quick-decision bridge (worker half included) + idle detection and toast self-dismiss + withdrawing leftover toasts on return + toast tag length handling + the page's host-bridge probe / heartbeat / release and the shape of `debug().hostBridge` + external forwarding (Telegram's request shape, the `ok` / `error_code` verdict, retries on 429 and 5xx, the 4096 truncation, half-configured targets being dropped, and the settings page's token and chat ID inputs) + Goal rounds staying quiet (silent while a Goal projection is `active`, one alert for the last round once it stops, and an older host without projections still alerting), plus three desktop native-channel cases — a Windows native approval toast's body click switches only after the host focus route is posted (and a no-session click only raises), a Windows button-less native toast (both "needs you" and "reply finished" bypass the renderer, the body click raises and then stops the poll, "never close" marks `persist`, and a host 5xx falls back to the page channel), and a macOS frontmost click switches through the 1 s poll and stops polling once read. It also pins the notification icon to the host route's `/__dsh-notify-me/icon.png` (no longer the root favicon), and that a cue's wake-back follows the audio clock rather than the wall clock — under a late wake (420 ms) the last note still completes, and a second cue on an already-slept context still parks after its own last note. The badge case counts conversations: two waiting ones report 2, an identical snapshot repaints nothing, the current conversation is excluded, muting or switching it off goes back to zero, and a host without `setAppBadge` stays silent instead of throwing. `dockBadgeHostFailures()` covers the failure side: a throwing snapshot still lets the switch apply, the error lands in `debug().dockBadgeError`, the count repaints once the store recovers, and a host that only ships `setAppBadge` clears with zero. It also pins the manifest: `package.json`'s `dsh.client.inject` must stay empty and the runtime line `inject = ["sessions", "locale", "slots"]` must stay as it is ([#44](https://github.com/chromoany/dsh-notify-me/issues/44): the loader reads that list as "arrive these whole bundles first", so an unreachable target leaves the whole entry silently inert). `smoke/host-route-test.mjs` needs no local DSH and runs the `lib/index.js` route, its probe and the 403/405/501 gate on every platform.

The three new suites also ship their own fake `ctx`, need no local DSH and touch no network: `smoke/page-bridge-test.mjs` runs the page-bridge route — status shape, heartbeat and release, missing intent header `403`, cross-origin `403`, bad JSON `400`, oversized `413`, the `allowedOrigins`-derived `Host` (a simulated tunnel) being let through, and path collisions; `smoke/host-fallback-test.mjs` runs the host fallback — approval dedupe, `turn/end` throttling, subagent skip, no push for a middle Goal round while the Goal is `active` (still pushing after `complete` / `pause` / `block`, and recovering the Goal state from the session log after a restart), no push on a fresh lease, a push after the lease expires, an immediate push after `alive:false`, language following the heartbeat, credentials re-read after a 401, and the health probe; `smoke/relay-route-test.mjs` runs the relay — the `GET` probe, `405`, cross-origin `403`, `413`, `400`, `503`, the `200` / `502` mapping and "retry exactly once on a 401", `relay.bodyTemplate` rendering and JSON escaping, a broken template registering no route at boot, and the rendered-size cap; 1.24.0 adds two more groups: a completion's body filled from the session log (newlines kept, clamped then truncated, a page body with a second line not overwritten, `attention` left alone), and `snippetLimit: 0` forwarding the session label only, while a request arriving on a public `Host` passes the gate and still reads no log.

`smoke/mac-notify-test.mjs` runs the macOS notification route: registered only on the macOS desktop host, the probe, the `405` / `403` / `501` / `400` refusals, the arguments handed to the helper (including `--id` / `--sound` and `{remove:id}` withdrawal), and the click hand-off being taken exactly once. It fakes the platform and Electron version, needs no real helper, and runs on every platform.

`smoke/mac-notify-content-test.mjs` runs the notification content: what `splitNotificationBody()` does with every shape a body arrives in (one line, two lines, blank lines, outer whitespace, CJK, missing fields), a subtitle the page lifted itself winning over the split, `--subtitle` being passed only when there really is one, the body never becoming the title (the regression), how the reply excerpt is taken from the event log (tool results skipped, collapsed to one line, cut and ellipsised when long, an empty log is not an error, and only read for a `done` alert with an empty body), a failed log read still posting the alert, and each half being cut to its own bound after the split (1000 characters for the body, 200 for the subtitle). It fakes the spawn too, needs no real helper, and runs on every platform.

Language and the Android fallback each get their own cases: `languageModes()` in `smoke/smoke-test.cjs` covers both `auto` sources (the host locale and `document.documentElement.lang`), `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` all resolving to Traditional, `zh-CN` staying Simplified, an unshipped UI tag (`ja` / `de`) reading English, the Simplified default only when the page carries no language signal at all, a pinned language flipping both the alerts and the Settings page, and the four dictionaries holding exactly the same key set; `androidWorkerFallback()` covers three paths — on an Android UA the constructor is never touched, exactly one Service Worker is registered, and the alert options (tag / renotify / silent / data) are right; on a desktop UA whose constructor throws `Illegal constructor` the first alert tries it as usual, falls back to the Worker and remembers the failure; and a Worker that refuses too leaves the error in `debug().lastToastReject` instead of swallowing it. `smoke/page-bridge-test.mjs` additionally pins that a `zh-TW` and a `ru` heartbeat are accepted, an unknown language is ignored, and the host-fallback copy and `pickLanguage` precedence follow.

`smoke/win-toast-test.mjs` runs the Windows native-toast route: the Windows desktop gate, the `GET` probe, the `405` / `403` / `501` / `400` refusals, the approval payload and its base64 pass-through, the seven registration commands written before the first toast (the three protocol keys under `HKCU\Software\Classes\dsh-notify-me`, `DisplayName` plus `IconUri`, and `CustomActivator` under `AppUserModelId\dsh-notify-me`, and an empty `CLSID\{…}` stub with no `LocalServer32`), eight on Windows 10 (adding `LocalServer32` pointing at `lib/win-toast-activator.ps1`), the `comActivation` and `persist` flags in the payload (a "never close" button-less alert going out with `scenario="reminder"`), and the `LPWStr` marshalling annotations in the activator callback, approve / reject / open actions being claimed once, token expiry, and `{remove}` withdrawal. A missing icon file still registers fine and simply skips `IconUri`. It drives `reg.exe` / `powershell.exe` through a fake `spawn`, so it needs no real Windows desktop host and runs on every platform. It also asserts the generated handler script is UTF-16LE with a BOM, pure ASCII, carries the `ExpandEnvironmentStrings` expression, and bakes in no profile path, and that the toast body launches only `dsh-notify-me://open` (never `dsh://open`); a no-session `dsh-notify-me://open` still parses as a plain raise request ([#40](https://github.com/chromoany/dsh-notify-me/issues/40)).

When `lib/focus-window.ps1` changes (Windows only), also run it by hand:

```powershell
powershell -NoProfile -File lib/focus-window.ps1 -ProcessId 0   # the last line should be FOCUSED=1
```

`cordis-host-test.mjs` borrows `@deepseek-ai/cordis` from a local DSH installation (it probes the global npm directory, `~/.dsh/profiles/web/node_modules` and the flat fallback `~/.dsh/profiles/node_modules` in turn); in a source checkout with no profile dependencies, point it there with `DSH_CORDIS_PATH=<checkout>/vendor/cordis/lib/index.js`.
