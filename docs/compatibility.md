# 兼容性

逐版本适配记录见 [package.json](../package.json) 的 `dsh.compatibility.dshReleases`；宿主（`0.2.1-rc.2` 及之后）的安装门控只读 `peerDependencies` 与 `engines`，**不再读取这个字段**，所以它只是一份给人看的记录，不构成门禁。

已逐版实测**真正激活**于 `0.1.1-rc.2`、`0.1.2-rc.1`、`0.1.5-rc.1`、`0.1.5-rc.2`、`0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5`、`0.2.2-alpha.2`、`0.2.2-rc.1`、`0.2.2-rc.2`、`0.2.2-rc.3`、`0.2.2-rc.4` 与 `0.2.2-rc.5`（判定标准：插件条目进启动页 `__DSH_BOOT__`、注入依赖解析通过、`/plugins/??dsh-notify-me/client.js&rev=…` 返回含新代码的构建、设置里出现「通知提醒」分区）。`0.2.2-rc.3` 的隔离跑在 2026-11-17 补齐（细节见下），设置分区、开关往返与四条宿主路由都实测过；桌面端另有 [#41](https://github.com/chromoany/dsh-notify-me/issues/41) 报告人在同一版本上的实测：1.21.2 把通知发到插件自有 AUMID（抬头 `DSH Notify Me`）、宿主半真的起了 `powershell.exe`；1.21.3 只加了 Windows 10 的 build 判定，没有碰宿主 API。`0.1.1-rc.2` 到 `0.2.2-rc.5` 的插件条目照旧兼容，换回旧宿主也不需要改配置；`1.9.0` 的界面重排没有引入新的宿主 API，设置页页眉的铃铛是插件自己画的 SVG（`docs/brand/`）。

<summary>展开宿主代际的形状差异与两个已知坑</summary>

插件按宿主代际自动选源；下表是各形状的边界，不是门禁：

| 宿主代际 | 「需要你」交互来源 | 判断当前会话 | 点通知切会话 |
| --- | --- | --- | --- |
| `≤ 0.1.2-alpha.1` | 控制器快照的 `pending[]` | 快照 `current` | `sessions.open()` |
| `0.1.2-alpha.2 .. 0.1.6-alpha.1` | `uiSession.pendingInteractions` | 快照 `current` | `sessions.open()` |
| `≥ 0.1.6-alpha.2`（含 `0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.5`、`0.2.2-alpha.2`、`0.2.2-rc.1`、`0.2.2-rc.2`、`0.2.2-rc.3`、`0.2.2-rc.4`、`0.2.2-rc.5`） | `uiSession.sessionStatus` | `retainedBy.mainView` | `uiWorkspace.openSession()` |

区间仅作示意：插件按 store 形状自动选源（`sessionStatus` 存在即走新路），版本号只是各形状的出现边界。`peerDependencies` 范围决定 npm 的 peer 提示——`0.2.1-rc.2`、`0.2.2-alpha.2`、`0.2.2-rc.1`、`0.2.2-rc.2`、`0.2.2-rc.3`、`0.2.2-rc.4` 与 `0.2.2-rc.5` 都落在 `>=0.2.0-rc.1 <0.3.0-0` 里，不需要豁免。

`0.2.2-rc.2` 的隔离验证（2026-11-13）：76 个启动条目（bootstrap 1 个，`application` 批 57 + 18 个），`dsh-notify-me` 在第二个 `application` 批里，三个注入目标（`client-ui-session`、`client-locale`、`client-ui-conversation`）都在；`/plugins/??dsh-notify-me/client.js&rev=…` 返回 275,450 B，即仓库 1.20.1 的 `lib/client.js`（275,380 B）加宿主 70 B 的 sourceMappingURL 注释，HTTP 200；无头 Edge 经 CDP 载入真实页面后 `apply` 正常执行，`debug()` 报 `version: 1.20.1`、`uiSession: bound`（页面刚开是 `unbound`，打开会话后转 `bound`，仍是惰性时序），从账号菜单进设置点开「通知提醒」渲染出整块视图，页脚显示「插件版本：dsh-notify-me v1.20.1」，通用设置里宿主版本为 `0.2.2-rc.2`。宿主客户端 bundle 相对 `0.2.2-rc.1` 仍有改动，但本插件依赖的 `uiSession.sessionStatus`、`retainedBy.mainView`、`uiWorkspace.openSession()` 与三个注入目标都没变。

`0.2.2-rc.3` 的隔离验证（2026-11-17）：启动载荷仍是 76 个条目（1 + 57 + 18 批），`dsh-notify-me` 在第二个 `application` 批、rev `0a8e1114c5e3`，三个注入目标都在；`/plugins/??dsh-notify-me/client.js&rev=…` 返回 287,814 B，即 1.21.3 的 `lib/client.js`（287,744 B）加 70 B 的 sourceMappingURL 注释，HTTP 200。rc.3 起 Web 宿主**要求 `?token=`**：裸 `GET /` 回 401，只有启动时打印的 `?token=…` 能开页面（桌面壳改成转发 `x-dsh-auth-token` 头，`lib/main.js`），所以这轮的 CDP 检查都带着 token。无头 Edge 载入真实页面后 `apply` 正常执行，`debug()` 报 `version: 1.21.3`、`uiSession: bound`、`uiSessionSource: sessionStatus`、`bridge: active`、`hostEnvDetected: web`、`raiseChannel: window-focus`、`notifyTagLimit: 64`、`configStored: true`；设置里「通知提醒」分区渲染完整、页脚「插件版本：dsh-notify-me v1.21.3」，通用设置里宿主为 `0.2.2-rc.3`，把「启用提醒」拨到关再拨回来，`debug().enabled` 跟着 `false`→`true` 往返。宿主半四条路由都在：`POST /__dsh-notify-me/focus-window` 回 `501`（Web 端没有桌面壳）、`POST …/win-toast` 与 `POST …/mac-notify` 回 `405`（方法不对，路由已注册）、`GET …/host-bridge` 回 `404`（默认关闭时本来就不注册，`debug().hostBridge.state` 是 `unavailable`）。宿主日志只有一行启动地址，没有 warning、没有 `pending` 断言。客户端 bundle 侧：`sessionStatus` 在，`pendingInteractions` 已从 rc.3 的会话 bundle 里消失（插件按 store 形状选源，不受影响）；当前会话的推导与 rc.3 自己的 `dsh-client-ui-workspace` / `dsh-client-ui-session` 是同一个表达式 `(session.retainedBy.mainView ?? 0) > 0`；四个会话行槽位与 `uiWorkspace.openSession()` 都在；`@deepseek-ai/dsh-client-ui-primitives` 在 rc.3 里既不单独发包、也不在启动条目里，插件那句 `require` 落进 try/catch 走本地 `role="menuitem"` 兜底，右键菜单项照旧可用。cordis 从 4.0.5 升到 4.1.0，宿主与插件两侧都没出弃用告警。无头环境里 `Notification.permission` 是 `denied`，设置页的测试按钮因此按设计报「未授权」而不是假装发出；系统通知一条没发属于无头限制，不是 rc.3 的行为差异。

`0.2.2-rc.4` / `0.2.2-rc.5` 的隔离验证（2026-11-19）：两版启动载荷都是 76 个条目（与 rc.3 同一形状，bootstrap 1 个 + `application` 批 57 + 18），`dsh-notify-me` 都在 index 65（第二个 `application` 批），三个注入目标 `client-ui-session` 18、`client-locale` 13、`client-ui-conversation` 30 都排在插件之前；插件条目自带 `rev`（rc.5 为 `30e84a2e01d7`），`/plugins/??dsh-notify-me/client.js&rev=…`（用条目自己的 `rev`，不是 boot 的）返回 200 / 282,966 B，即 1.21.5 的 `lib/client.js` 加宿主 70 B 的 sourceMappingURL 注释。无头 Edge 经 CDP 载入带 `?token=` 的真实页面后 `apply` 正常执行：`window.__dshNotifyMe` 是对象，`debug()` 报 `version: 1.21.5`、`uiSession: bound`，76 个启动条目、控制台零报错。宿主 API 面是把 76 个客户端 bundle 全下载后按字符串核的（bundle 按需拉取，光看启动页 HTML 搜不到）：`sessionStatus`、`retainedBy`、`completionUnread`、`pendingInteraction`、`settings.section`、三个会话行槽位（`sidebar.workspaces.session.row.action`、`sidebar.session.row.leading`、`sidebar.workspaces.session.menu.item`）、`uiWorkspace.openSession` 与审批契约 `allowed-once` 十项全在。`npm test` 用 rc.5 自带的 cordis 4.1.0 跑，八套件全过（日志含 `watcher bound OK to sessionStatus`、`current-session derivation OK (retainedBy.mainView)`、`toast click navigated via uiWorkspace.openSession OK`、`quick decision via decide() OK: ["allowed-once"]`）；`DSH_CORDIS_PATH` 要指到 `@deepseek-ai/cordis/lib/index.js`，给目录会报 `ERR_UNSUPPORTED_DIR_IMPORT`。上游 release notes：rc.4 是两项 bugfix（异常模型响应处理、桌面端 LiveShare 分享），rc.5 是 DeepSeek 模型改走服务端搜索、不计次收费，都没有动客户端插件 API。

`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5`、`0.2.2-alpha.2` 与 `0.2.2-rc.1` 各跑了一轮隔离验证：隔离 `DSH_HOME` 装好插件再起 `dsh web --no-open`（`rc.3` / `rc.4` / `rc.5` 都是 71 个启动条目，`0.2.2-alpha.2` 72 个，`0.2.2-rc.1` 74 个），插件条目 `dsh-notify-me` 都在 `application` 批（`0.2.2-rc.1` 把启动载荷改成 entries + batches、按批合并加载，插件条目本身没变），三个注入目标（`client-ui-session`、`client-locale`、`client-ui-conversation`）都在；`/plugins/??dsh-notify-me/client.js` 返回当时的构建（`rc.3` / `rc.4` 是 1.16.1 的 248,023 B，`rc.5` 是 1.17.0 的 252,562 B；`0.2.2-rc.1` 返回的就是仓库里 1.17.0 的 `lib/client.js`，宿主只在末尾追加 70 B 的 sourceMappingURL 注释，HTTP 200）；无头 Edge 经 CDP 载入真实页面后 `apply` 正常执行，`debug()` 报 `uiSession: bound`、`uiSessionSource: sessionStatus`、`raiseChannel: window-focus`（`0.2.2-rc.1` 另核了 `version: 1.17.0` 与 `notifyTagLimit: 64`；页面刚开、还没打开会话时 `uiSession` 是 `unbound`，点开一个新会话后约 1.5 秒转为 `bound`，是插件惰性查找服务的正常时序），从账号菜单进设置点开「通知提醒」能渲染出整块设置视图（`0.2.2-rc.1` 还显示「插件版本：dsh-notify-me v1.17.0」，通用设置里宿主版本为 `0.2.2-rc.1`），Web 宿主全程没有 warning/error（唯一一条 404 是桌面 Electron 页面桥 `/__dsh-notify-me/host-bridge` 的可选探测，插件自己把 `hostBridge.state` 标成 `unavailable`，不影响提醒）。四版的宿主客户端 bundle 相对 `0.2.1-rc.2` 都有改动（`dsh-client-ui-workspace`、`dsh-client-ui-conversation`、`dsh-client-locale` 等），但本插件用到的四个会话行槽位、`uiSession.sessionStatus`、`retainedBy.mainView`、`uiWorkspace.openSession()` 一个没少；`0.2.2-alpha.2` 另加了 `sidebar.session.row.trailing`，与本插件无关；`0.2.2-rc.1` 又改了 `dsh-client-ui-session`、`dsh-client-ui-workspace`、`dsh-client-ui-conversation`、`dsh-client-locale`、`dsh-client-modules` 与 `dsh-client-ui-approval` 的客户端 bundle，这些面仍然都在。`0.2.1-rc.5` 的桌面壳 `lib/main.js` 仍是通用转发（没有按路由做白名单），Windows 抬窗那条插件 exact 路由不受影响；`0.2.2-rc.1` 的桌面壳同样通用转发、仍不注册 Service Worker，并在安装版桌面（Windows）上实测了该路由：GET 200，坏 `Host` / 跨源 / 错误方法分别 403 / 403 / 405，POST 真的把窗口抬到前台。宿主侧形状仍与 `0.2.0-rc.2` 一致，不需要改代码。

两个坑值得记住：一是 `dsh.client.inject` 会被宿主加载器读成「先让这些整包到达，再跑我这一条」——目标在该宿主上到不了，客户端条目就停在 `pending` 而永不执行，页面既不报错也没有 `window.__dshNotifyMe`（1.1.3 在 `0.1.2-rc.1` 及以后是这样失效的，1.21.4 在桌面 `0.2.2-rc.3` 上又这样失效了一次，见 [#44](https://github.com/chromoany/dsh-notify-me/issues/44)）；所以 1.21.6 起这个字段固定为空数组，本包只保留运行时那句 `inject = ["sessions", "locale", "slots"]`，`uiSession` / `uiWorkspace` 一律 `ctx.get()` 惰性取，缺了只降级；二是宿主换存储或字段名时**不会报错**，提醒只会静默失效——`pendingInteractions`→`sessionStatus`、`list.current`→`retainedBy.mainView`、`sessions.open()`→`uiWorkspace.openSession()` 都是这一类，所以每次适配都要用 `window.__dshNotifyMe.debug()` 确认真的是 `bound`。
